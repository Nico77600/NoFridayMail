# NoFridayMail

An Outlook add-in (Smart Alerts) by Nicolas Fabert that stops mail and meeting invitations from leaving on the days you choose (Friday by default) and offers the next working day instead. This folder contains everything needed to deploy and use it in your own Azure subscription: the deploy script and its tools, the add-in sources and the small API of the optional exceptional send, the environment schema with an example, the manifest and site files, and both guides. Tests, CI and the developer tools stay outside it, in the repository.

> [!IMPORTANT]
> Files downloaded from the Internet may be blocked by Windows. Unblock them once, from this folder:
>
> ```powershell
> Get-ChildItem . -Recurse -File | Unblock-File
> ```

## Requirements

- PowerShell 7.4 or later, to run the deploy script.
- Node.js 22 or later with npm (the build uses webpack; the managed API runs on Node 22).
- Azure CLI, signed in (`az login`), and a subscription where you can create a resource group and a Static Web App (*Contributor*). The Free plan is enough.
- Microsoft 365 with Exchange Online mailboxes; the *Global Administrator* or *Exchange Administrator* role to publish the manifest to a group or to the company.
- Optional exceptional send: a Microsoft Entra app registration, a Conditional Access authentication context requiring MFA, an Exchange transport rule and, for traces, Application Insights.

## Quick start

```powershell
# In PowerShell 7, in the folder of the add-in (the unpacked release ZIP), files unblocked
cd C:\Tools\NoFridayMail

# 1 · Install the tools once (PowerShell 7.4+, Node.js 22+, Azure CLI), then sign in to Azure
az login

# 2 · Create your environment: one small file with the Azure names and the blocked days.
#     Its add-in Id is generated once and kept for good.
pwsh .\tools\New-NoFridayMailEnvironment.ps1 -Name contoso
notepad .\deploy\environments.local\contoso.json

# 3 · Simulate: shows the checklist and every step, creates nothing
pwsh .\tools\Deploy-NoFridayMail.ps1 -Environment contoso -WhatIf

# 4 · Deploy the site: creates the Azure resources if needed, builds, deploys and checks it
pwsh .\tools\Deploy-NoFridayMail.ps1 -Environment contoso

# 5 · Install dist\contoso\manifest.prod.xml in Outlook (the user guide, chapter 4 for a test, chapter 5 for everyone)
```

## Data handling

The add-in reads only the delivery time of the item being sent and the clock; it does not read message content or recipients and stores nothing. With the exceptional send enabled, the justification and the identity of the user go to the managed API of your own Azure Static Web App, which logs them to your Application Insights. Nothing is sent to the author.

The release ZIP carries `PackageIntegrity.psd1`: the owner's Authenticode signature on the PowerShell files and the manifest, and the SHA-256 of every file. `tools\Test-PackageIntegrity.ps1 -Root .` verifies it; the deploy script does so first. A package built by CI is unsigned and is not for deployment. Obtain releases only from the official repository.
